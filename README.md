# RVQ AE for MiniMax Music 3

An open audio to RVQ code encoder for MiniMax Music 3 by Munaza Ashraf and bghira, written
as a self contained research codebase: the model, the timeline contract between DAV latents
and RVQ frames, the reverse distillation objective, the muP parametrisation, a torchrun
trainer, an evaluation harness and an HTTP service. The released weights on the Hub load
directly.

The encoders, the reverse distillation dataset and the experiments behind them are joint work
by the two authors; the v1 to v4 training runs were carried out in SimpleTuner and this
repository is the standalone reference implementation of that work.

MiniMax Music 3 plans a track as eight integer streams at 25 Hz (one semantic codebook of
16,384 entries and seven acoustic codebooks of 1,024 entries), then renders those codes with
a diffusion transformer over 128 channel DAV latents. The encoder that would turn audio back
into codes was never released. This project learns that missing map from tracks generated by
the model itself, so that a reference recording can condition new generations.

## Results

Condition replay cosine on 130 held out tracks: the reference audio is encoded to codes, the
codes are replayed through the official language model path, and the resulting condition
embedding is compared with the one produced from the true sampled codes. The pipeline control
(true codes) scores 0.9999.

| Model | Parameters | Change | Replay cosine |
|---|---:|---|---:|
| community proof (Serveurperso) | 41M | single GPU baseline | 0.6633 |
| v1 | 40,978,944 | eight independent heads, teacher top 50 KL, muP | 0.7624 |
| v2 | 154,736,064 | shared width 512 to 1,088 | 0.7698 |
| v3 | 154,736,064 | v2 plus a training only MERT alignment term | 0.7703 |
| v4 | 169,008,576 | causal decoder across codebook depth | 0.8748 |

Exact token agreement of v4 on the held out split (step 17,500):

| Metric | Free running | Teacher forced |
|---|---:|---:|
| semantic top 1 | 43.16% | 43.16% |
| semantic top 5 | 80.51% | 80.51% |
| acoustic top 1 | 7.30% | 18.42% |
| acoustic top 5 | 19.88% | 44.54% |

This implementation reproduces those figures on the full holdout (see Reproduced evaluation
below), and the re encoded DAV latents match the generator's stored latents with 0.986 mean
cosine at zero lag.

Exact agreement is a weak proxy. The code space is redundant: different code tuples map to
nearly the same downstream condition, which is why v4 improves replay cosine by 0.10 while
its free running acoustic top 1 drops slightly. Full experiment provenance and per track
statistics are published with the weights (see Links).

## Pipeline

    waveform, 44.1 kHz, stereo
      -> DAV encoder (frozen): 1024 channels at hop 512, posterior mean 64 channels per side
      -> latents [L, 128] at 86.1328125 Hz
      -> conv stem and three dilated residual blocks at latent rate
      -> mean pooling with the per track operator P onto 25 Hz frames
      -> learned frame positions, eight bidirectional pre norm transformer layers
      -> semantic logits (codebook 0)
      -> causal depth decoder: acoustic codebook k given the frame context,
         the semantic code and acoustic codebooks below k
      -> codes [T, 8]

The encoder sees 128 frames (5.12 s) at a time and keeps no state across windows. The DAV
encoder runs in 30 s segments with a 1 s margin on each side (its receptive field is about
0.56 s), so memory stays flat for tracks of any length and the result equals a single pass.

## Timeline contract

The generator renders 200 frame chunks with a 100 frame hop and stitches the DAV latents
with a hop of 345 latents (floor(100 x 441 / 128)). Frame t therefore covers a variable
latent span [s_t, e_t) rather than a fixed stride of 441 / 128 = 3.4453 latents. The
alignment module computes the n + 1 boundaries of a track and the pooling operator

$$P_{t,l} = \frac{1}{e_t - s_t} \quad \text{for } l \in [s_t, e_t), \qquad 0 \text{ otherwise},$$

so that every row of P sums to one and the pooled feature of a frame is the mean of the
latent features it was rendered from. Every row of P is a contiguous constant block, so the model
evaluates it as a segment mean in O(L d) rather than as a dense product in O(T L d); the dense
matrix remains as the definition the tests check the segment form against.

When the dataset records the chunk stitching table, boundaries come from it exactly: chunk 0
owns frames [f_0, f_1 + 25), chunk i owns [f_i + 25, f_{i+1} + 25), the last chunk owns
through its own end, and owned frames map linearly (integer ceiling) onto the kept latents
of that chunk. Without the table the nominal reconstruction is used: with W = max(1, (n - 1) // 100)
chunks, frame f belongs to chunk c = clamp((f - 25) // 100, 0, W - 1), a chunk of cf frames
yields cl = floor(cf x 441 / 128) latents, and

$$s_f = 345\,c + \left\lceil \frac{(f - 100c)\, cl}{cf} \right\rceil .$$

Invariants checked by the tests: s_100 = 345, s_200 = 690, s_4500 = 15,524, every span holds
three or four latents.

## Model

Component sizes of the recommended v4 configuration (width d = 1,088, 17 heads of dimension
64, feed forward 4d, depth decoder width 512):

| Component | Parameters |
|---|---:|
| latent stem, Conv1d 128 to d, kernel 7 | 975,936 |
| three residual blocks (GroupNorm, dilated 3 tap conv, 1 tap conv) | 14,217,984 |
| learned positions, 128 x d | 139,264 |
| eight transformer layers, 12 d^2 + 13 d each | 113,752,576 |
| output LayerNorm | 2,176 |
| semantic readout, d to 16,384 | 17,842,176 |
| depth decoder (context projection, prior embeddings, two causal layers, seven heads) | 22,078,464 |
| total | 169,008,576 |

The temporal stack runs fused scaled dot product attention, which on Ampere selects a Flash or
memory efficient kernel; the depth decoder runs the unfused path, which is measurably faster at its
sequence length of 8 (see Benchmarks). The depth decoder runs independently for each frame over the sequence
[context, e_0(c_0), e_1(c_1), ..., e_6(c_6)] with learned depth positions and a causal mask.
Head j reads position j + 1 and predicts acoustic codebook j + 1. Training teacher forces the
sampled codes; inference feeds back greedy predictions. State dict keys match the published
checkpoints, so v1 to v4 load with strict key checking.

## Objective

With K = 8 codebooks, hard targets c and the generator's stored top 50 distribution
(ids i and logits z_T) per frame,

$$\mathcal{L} = \frac{1}{K}\sum_{k} \mathrm{CE}_k + w_{KL}\,\frac{1}{K}\sum_{k} \mathrm{KL}_k, \qquad
\mathrm{KL}_k = \tau^2 \sum_{i \in \text{valid}} p_T(i)\,\big(\log p_T(i) - \log p_S(i)\big),$$

where p_T is the softmax of z_T / tau over the valid stored ids, p_S is the student softmax
over the whole vocabulary at temperature tau gathered at those ids, and ids outside the
vocabulary (padding, the semantic end of track id 16,384) are dropped. The released models
use w_KL = 0.25 and tau = 1.

## muP

The shared encoder follows the maximal update parametrisation (Yang et al., Tensor Programs V,
2022) with width multiplier m = d / 128 (8.5 for v4), implemented in three rules:

1. readouts from the width dimension compute W (x / m) + b;
2. attention logits are scaled by 8 / d_head instead of 1 / sqrt(d_head);
3. AdamW learning rate of matrix like weights (both dimensions grow with d) is divided by m
   and their weight decay multiplied by m.

At initialisation, biases fed by a width sized fan in and non zero readouts are multiplied by
sqrt(m). The semantic readout is zero initialised so the initial semantic distribution is
uniform. The fixed width depth decoder uses standard layers except its context projection.
No external muP package or base shape files are needed: the base width is part of the config.

## Data

Dataset: bghira/minimax-music3-rvq-reverse-distillation, 2,972 tracks generated by MiniMax
Music 3 with their sampled codes, teacher top 50 ids and logits, and the chunk stitching table
(about 178 GB). Waveforms are encoded once through the DAV encoder into a latent cache; training
reads 128 frame windows from it. Only records with an exact stitching table are used.

## Benchmarks

Measured on an RTX 3090 (sm_86, 23.6 GiB, driver 580.173.02), torch 2.14 on CUDA 13, Python 3.13,
bf16 autocast and tf32; median device time, peak allocation of the measured region. Regenerate everything with

    uv run rvq-ae bench --device cuda --suite all

| Measurement | Result |
|---|---:|

| fused attention at the depth decoder shape (b2048, 8 heads, 8), forward / backward | 2.9x / 3.8x slower, so that stack stays unfused |

## Installation

Python 3.13 and uv:

    git clone https://github.com/MunazaAshraf10/open-rvq-encoder-minimax-music3
    cd open-rvq-encoder-minimax-music3
    uv sync --all-extras

The extras are serve (FastAPI service), train (Weights and Biases logging) and dev (tests,
ruff, mypy). Training and serving default to CUDA; every command accepts --device.

## Usage

Encode a file with the recommended release:

    uv run rvq-ae encode --audio reference.flac --out codes.safetensors --topk 5

Build the latent cache, then train v4 on four GPUs and score every checkpoint:

    uv run rvq-ae cache --split train --split holdout
    uv run torchrun --nproc_per_node 4 -m rvq_ae train --config configs/v4_169m.json
    uv run rvq-ae evaluate --run output/v4-169m --split holdout

Measure the implementation on the local GPU:

    uv run rvq-ae bench --device cuda --suite all

Serve the model:

    uv run rvq-ae serve --port 8000
    curl -F file=@reference.flac -F topk=5 http://localhost:8000/encode
    curl -H 'Content-Type: application/json' -d '{"reference": [[1,2,3,4,5,6,7,8]], "predicted": [[1,2,3,4,5,6,7,0]]}' http://localhost:8000/evaluate/codes

Endpoints: GET /health, GET /model, POST /encode (audio file or a safetensors file holding
latents [L, 128]; form fields topk, confidence, output=json|safetensors), POST /evaluate/codes,
POST /evaluate/audio (audio plus reference codes as JSON; reports top 1 and top 5 per codebook).
Settings come from the command line or RVQ_AE_MODEL, RVQ_AE_VARIANT, RVQ_AE_DAV, RVQ_AE_DEVICE
and RVQ_AE_MAX_SECONDS.

From Python:

    import torch
    from rvq_ae.audio import load_audio
    from rvq_ae.inference import CodeEncoder

    codec = CodeEncoder.load(variant="v4", device="cuda")
    audio, rate = load_audio(Path("reference.flac"))
    result = codec.encode(audio, rate, topk=5)
    result.codes          # [frames, 8] int64
    result.confidence     # [frames, 8] probability of each chosen code
    result.semantic_topk  # [frames, 5] candidate semantic codes

Push a trained checkpoint to the Hub:

    uv run rvq-ae push --folder output/v4-169m/final --repo your-name/rvq-encoder --path-in-repo final

## Reproduction notes

The v4 release was trained for 17,660 optimizer steps (20 epochs, batch 16 per rank on four
GPUs), AdamW with learning rate 3e-4, weight decay 0.01, 500 warm up steps followed by linear
decay to 1e-7, gradient clipping at 1.0, bf16 autocast, seed 42. configs/v4_169m.json holds
these values; configs/v1_41m.json is the 41M baseline. configs/v4_169m_single_gpu.json keeps the
same effective batch of 64 windows on one GPU through gradient accumulation; on an RTX 3090 a step
takes 396 ms and peaks at 5.3 GiB, so the run is about 1.9 hours of compute (see Benchmarks).
Training resumes bitwise from any checkpoint folder: weights, optimizer, scheduler and per rank
random state are stored.

Two details differ from the published inference adapter and are chosen deliberately:

- the semantic readout and the depth context projection divide their input by m, as they did
  during training; the adapter applies the same weights without that division. On a held out
  track this leaves semantic top 1 unchanged (43.6% against 43.5%) but lowers free running
  acoustic top 1 from 7.1% to 5.8%, because the context projection feeds a nonlinear decoder.
  The 0.8748 replay figure was measured through the adapter;
- without a stitching table the nominal timeline above is used, which is the rule the training
  alignment converges to; the adapter uses a fixed 441 / 128 stride.

## Testing

    uv run pytest
    uv run ruff check src tests
    uv run mypy src

The suite builds the released configurations on the meta device and checks parameter counts and
state dict keys against the published checkpoints, verifies the alignment invariants, the loss
identities, weight norm folding against torch, the causal property of the depth decoder, and that
resuming a run reproduces an uninterrupted run bitwise. It also proves the two performance changes
are transparent: the segment pooling operator equals the dense matrix to machine precision in
float64, and the fused attention kernel matches the unfused reference to the resolution of the
dtype. Cases that need a GPU are skipped when none is present. tests/test_style.py enforces the
repository conventions, so they cannot drift.
