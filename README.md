# RVQ AE for MiniMax Music 3

An open audio to RVQ code encoder for MiniMax Music 3 by Munaza Ashraf and bghira: the model,
the timeline contract between DAV latents and RVQ frames, the reverse distillation objective,
the muP parametrisation, a torchrun trainer, an evaluation harness and an HTTP service. The
released weights on the Hub load directly. The v1 to v4 training runs were carried out in
SimpleTuner; this repository is the standalone reference implementation of that work.

MiniMax Music 3 plans a track as eight integer streams at 25 Hz (one semantic codebook of
16,384 entries and seven acoustic codebooks of 1,024 entries), then renders those codes with a
diffusion transformer over 128 channel DAV latents. The encoder that would turn audio back into
codes was never released. This project learns that missing map from tracks generated by the
model itself, so that a reference recording can condition new generations.

## Results

Condition replay cosine on 130 held out tracks: the reference audio is encoded to codes, the
codes are replayed through the official language model path, and the resulting condition
embedding is compared with the one produced from the true sampled codes (control 0.9999).

| Model | Parameters | Change | Replay cosine |
|---|---:|---|---:|
| community proof (Serveurperso) | 41M | single GPU baseline | 0.6633 |
| v1 | 40,978,944 | eight independent heads, teacher top 50 KL, muP | 0.7624 |
| v2 | 154,736,064 | shared width 512 to 1,088 | 0.7698 |
| v3 | 154,736,064 | v2 plus a training only MERT alignment term | 0.7703 |
| v4 | 169,008,576 | causal decoder across codebook depth | 0.8748 |

Exact token agreement of v4 on the held out split: semantic top 1 43.2%, top 5 80.5%; acoustic
top 1 7.3% free running and 18.4% teacher forced. Exact agreement is a weak proxy: the code
space is redundant, which is why v4 gains 0.10 replay cosine while its free running acoustic
top 1 drops slightly. Re evaluating the released weights with this implementation reproduces
every published row within 0.003 in loss and 0.001 in accuracy on the same 130 tracks and
2,768 windows.

## How it works

    waveform, 44.1 kHz stereo
      -> DAV encoder (frozen): posterior mean, 128 channels at 86.1328125 Hz
      -> conv stem and three dilated residual blocks at latent rate
      -> mean pooling onto 25 Hz frames with the per track operator P
      -> learned frame positions, eight bidirectional pre norm transformer layers
      -> semantic logits (codebook 0)
      -> causal depth decoder: acoustic codebook k given the frame context,
         the semantic code and acoustic codebooks below k
      -> codes [T, 8]

The generator renders 200 frame chunks with a 100 frame hop and stitches the latents with a hop
of 345, so frame t covers a variable span [s_t, e_t) of three or four latents rather than a fixed
441 / 128 stride. With the chunk table absent, W = max(1, (n - 1) // 100) chunks, frame f in chunk
c = clamp((f - 25) // 100, 0, W - 1), a chunk of cf frames yielding cl = floor(cf x 441 / 128)
latents, and s_f = 345 c + ceil((f - 100 c) cl / cf). The pooling operator P[t, l] = 1 / (e_t - s_t)
on [s_t, e_t) is evaluated as a segment mean, which the tests check against the dense matrix to
machine precision. The encoder sees 128 frames (5.12 s) at a time with no state across windows.

Objective with K = 8 codebooks, hard targets c and the generator's stored top 50 ids i and
logits z_T: L = mean_k CE_k + 0.25 mean_k KL_k with KL_k = tau^2 sum_i p_T(i) (log p_T(i) minus
log p_S(i)) over the valid stored ids at tau = 1. The shared encoder follows muP (width multiplier
m = d / 128): readouts compute W (x / m) + b, attention logits scale by 8 / d_head, and matrix like
weights take learning rate / m and weight decay x m; the base width is part of the config.

Training data: bghira/minimax-music3-rvq-reverse-distillation, 2,972 generated tracks with their
sampled codes, teacher top 50 ids and logits, and the chunk stitching table (about 178 GB).

## Benchmarks

Measured on an RTX 3090 (sm_86, 23.6 GiB) with torch 2.14 on CUDA 13 and Python 3.13; regenerate
with rvq-ae bench.

| Measurement | Result |
|---|---:|
| fused attention on the temporal stack (b16, 17 heads, 128), forward / backward | 3.6x / 2.8x faster than unfused |
| fused attention at the depth decoder shape (b2048, 8 heads, 8), forward / backward | 2.9x / 3.8x slower, so that stack stays unfused |
| pooling operator assembly on the host, batch 64 | 152.9 ms dense to 8.5 ms segment index |
| v4 training step, batch 16, forward and backward | 84.5 ms, 3.8 GiB |
| v4 single GPU recipe (batch 16 x accumulation 4), one optimizer step | 396 ms, 5.3 GiB; 1.9 h for 17,660 steps |
| end to end encoding of a 6 minute stereo track | 5.6 s, 64x real time, 4.4 GiB peak |

## Usage

Python 3.13 and uv:

    git clone https://github.com/MunazaAshraf10/open-rvq-encoder-minimax-music3
    cd open-rvq-encoder-minimax-music3
    uv sync --all-extras

Encode a file with the recommended release, or from Python:

    uv run rvq-ae encode --audio reference.flac --out codes.safetensors --topk 5

    from rvq_ae.audio import load_audio
    from rvq_ae.inference import CodeEncoder
    codec = CodeEncoder.load(variant="v4", device="cuda")
    audio, rate = load_audio(Path("reference.flac"))
    result = codec.encode(audio, rate, topk=5)   # result.codes [frames, 8], result.confidence

Build the latent cache, train v4 (four GPUs, or one 24 GB GPU with the single GPU config), score
every checkpoint, serve the model, push a checkpoint:

    uv run rvq-ae cache --split train --split holdout
    uv run torchrun --nproc_per_node 4 -m rvq_ae train --config configs/v4_169m.json
    uv run rvq-ae train --config configs/v4_169m_single_gpu.json
    uv run rvq-ae evaluate --run output/v4-169m --split holdout
    uv run rvq-ae serve --port 8000
    uv run rvq-ae push --folder output/v4-169m/final --repo your-name/rvq-encoder

The v4 release used 17,660 optimizer steps (20 epochs, batch 16 per rank on four GPUs), AdamW
at 3e-4, weight decay 0.01, 500 warm up steps then linear decay to 1e-7, gradient clipping at
1.0, bf16 autocast, seed 42; configs/v1_41m.json holds the v1 recipe with its cosine schedule.
Training resumes bitwise from any checkpoint folder. Every command accepts --device.

Two details differ deliberately from the published inference adapter: the semantic readout and
the depth context projection divide their input by m as they did during training, and without a
stitching table the nominal timeline above is used rather than a fixed 441 / 128 stride.
