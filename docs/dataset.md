encoder is trained to invert the generator on the generator's own outputs, which is the only
setting in which the true codes of a waveform are known.

## Shard contents

One track per ZIP shard, data/<batch>/shard-<id>.zip, holding audio.flac (stereo, 44.1 kHz),
prediction.safetensors, and metadata. The tensor file carries:

| Tensor | Shape | Used here |
|---|---|---|
| codes | [rows, 8] int16, row 0 is the priming row | yes, as targets |
| teacher_topk_ids | [rows, 8, 50] int32 | yes, distillation support |
| teacher_topk_logits | [rows, 8, 50] | yes, distillation targets |
| condition embeddings | stored per chunk | no (replay evaluation only) |
| flow_vae_latents | [128, latents] | no; the trainer re encodes audio.flac through the DAV encoder |

The stored latents are decoder path consistency targets, not the encoder input of the released
pipeline, so training inputs are always recomputed from the waveform.

## Index schema (indexes/*.jsonl)

One JSON object per shard: shard_id, path, size, prediction_id, predict_seconds,
estimated_cost_usd, dataset_split, sampling (the eight sampling fields above), alignment, and
manifest with model, model_version and jobs. Each job records id, status, audio_file,
tensor_file, prompt, lyrics, seed, requested_duration_seconds, num_inference_steps,
sampling_rate (44,100), frame_rate (25), latent_hop_length (512), flow_latent_length,
emitted_frames, priming_frames, condition_length, ended_by_eos, semantic_eos_code (16,384),
codebook_vocab_sizes, teacher_distribution, source_metadata and its own alignment block.
data/records.py parses exactly these fields; jobs whose status is not succeeded or whose
codebook count is not eight are rejected.

## Alignment convention (alignment block)

| Field | Value |
|---|---|
| codes_include_priming_row | true |
| priming_code_row | 0 |
| emitted_code_row_offset | 1: semantic frame i is supervised by codes[i + 1] |
| semantic_frame_rate_hz | 25 |
| flow_latent_rate_hz | 86.1328125 |
| nominal_flow_latents_per_semantic_frame | 3.4453125 |
| flow_latent_audio_sample_rule | stitched latent j starts at audio sample j x 512 |
| chunk_stitching | list of chunk_index, semantic_frame_start, semantic_frame_end_exclusive, stitched_flow_latent_start, stitched_flow_latent_end_exclusive; absent on legacy shards |

Chunk boundary rounding is not uniform, so consumers must use the stored table when present and
the nominal reconstruction of docs/formulas.md section 2.1 otherwise. Training and evaluation use
exact alignment only: records without a table are skipped (exact_only in the configs).

## What the latent cache stores (data/cache.py)

Per record: latents [latent_frames, 128] in bfloat16 from the frozen DAV encoder, codes as
int16, the teacher top 50 ids and logits, and a JSON sidecar with the frame counts, the presence
of teacher tensors, the exact flag and the mapped latent count. Windows are read with
safetensors slices, so no full track is loaded per crop. Building the 135 holdout records on an
RTX 3090 downloads about 8 GB and encodes 250 minutes of audio in a few minutes.
